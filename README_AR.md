# ALMANTHOMH EO CN — EAGLE NEXUS V5.0.0

إصدار مصدر يوسّع منصة الحسابات والأجهزة إلى **300 خانة هاتف موزعة على 6 مجموعات × 50، بالإضافة إلى 50 خانة كمبيوتر مستقلة**. يستخدم الموقع وتطبيق Android ونُسخة Windows PWA خادمًا وقاعدة بيانات مشتركين.

## ما ينفذه المصدر

- حسابات وجلسات آمنة، حماية CSRF، وتحديد محاولات الدخول وتفعيل الأكواد.
- حد أساسي ساعتان يوميًا، وكود المستخدم يرفعه إلى 6 ساعات يوميًا، وكود مطور منفصل يفتح حتى 24 ساعة يوميًا. كود المطور لا يمنح دور ADMIN.
- التحقق من الأكواد على الخادم فقط؛ لا يرسل الموقع الأكواد السرية إلى JavaScript.
- 300 خانة Android في ست مجموعات، و50 خانة كمبيوتر منفصلة PC-01 إلى PC-50 مع الحجز والتحرير والنبضات وإدارة المدير. يستطيع المدير إلغاء تفعيل الحساب وإرجاعه إلى حد المستخدم دون إنشاء صلاحية مطور.
- PWA للموقع على الكمبيوتر والهاتف؛ يمكن تثبيتها من Chrome أو Edge على Windows بعد النشر عبر HTTPS.
- تطبيق Android مصدره ضمن `android/`، مع شعار وخلفية النسر الجديدة. يدعم جلسة تطبيق مستقلة قبل ربط الهاتف عبر Bearer token محفوظ باستخدام Android Keystore، وتُحتسب نبضاته ضمن نفس رصيد الحساب. بعد ربط الجهاز تُستخدم هوية الجهاز لنبضات مشاركة الشاشة.
- ربط Android برمز لمرة واحدة صالح 15 دقيقة، وبث WebRTC للعرض فقط بعد موافقة صاحب الجهاز محليًا لكل جلسة.
- شاشة افتتاح EAGLE NEXUS تستخدم الصورة المرفوعة مع ظهور تدريجي من الظلام عبر CSS، وزر تخطٍ ودعم تقليل الحركة.
- مؤثرات نقر Web Audio اختيارية ولا تعمل قبل تفعيل المستخدم للصوت.

## الأكواد وحدود الاستخدام

الحساب الجديد يبدأ بحد ساعتين يوميًا، ويمكنه رفعه إلى 6 ساعات بتفعيل كود المستخدم بعد إعداد المصادقة الثنائية. يُدخل المستخدم كود المستخدم ورمز TOTP من لوحة الحساب أو تطبيق Android. في أول إعداد، يربط الحساب بتطبيق Authenticator من لوحة الموقع ثم يستخدم رمز TOTP عند تفعيل الكود من أي منصة. بعد تفعيل TOTP يصبح الرمز مطلوبًا عند كل تسجيل دخول جديد، وليس فقط عند تفعيل كود الاستخدام. كلمة المرور لا تُحفظ داخل التطبيق. هذا الكود يرفع الحد إلى 6 ساعات يوميًا. كود المطور يُنشأ من الخادم بسكربت `scripts/generate-developer-access-code.py` ويمنح 24 ساعة يوميًا فقط؛ ولا يغيّر `role` إلى `admin` ولا يتجاوز موافقة Android أو ضوابط الحماية.

يُقاس الاستخدام بواسطة نبضات نشاط الواجهة والخادم وفق توقيت القاهرة. حد الاستخدام ليس قياسًا لكل نشاط الهاتف خارج المنظومة. تبقى إجراءات تسجيل الخروج، إلغاء الجهاز، وإيقاف جلسة العرض متاحة كإجراءات أمان.

تسلسل قفل المصادقة: 3 رموز خاطئة تقفلها 10 دقائق؛ بعد انتهاء القفل، خطآن إضافيان يقفلانها 20 دقيقة، ثم كل خطأين يضاعفان المدة إلى 40 و80 دقيقة وهكذا، بحد أقصى 48 ساعة.

## مساحة المستخدم والإدارة

- مساحة المستخدم تحفظ الملاحظات والمهام والتفضيلات والإشعارات وقواعد الأتمتة وطلبات الدعم في قاعدة البيانات، مع التحقق من ملكية كل سجل.
- تتوفر تقارير الخصوصية والتشخيص والخط الزمني وتصدير/استيراد البيانات الشخصية. الاستيراد لا يقبل الجلسات أو رموز الربط أو مفاتيح الأجهزة.
- قفل الطوارئ يتطلب كلمة المرور وTOTP، ويُلغي الجلسات والأجهزة والربط والخانات الأخرى. حذف الحساب يتطلب إعادة تحقق ولا يسمح بحذف حساب مدير من واجهة المستخدم.
- يمكن للمدير تعيين مدير مجموعة واحدة من مجموعات الهاتف الست؛ يرى مدير المجموعة 50 خانة مجموعته فقط ولا يصل إلى المجموعات الأخرى أو مجموعة الكمبيوتر.

## Windows

نسخة الكمبيوتر هي الموقع نفسه كتطبيق PWA قابل للتثبيت من Chrome أو Edge، وليست EXE مستقلًا. راجع `docs/WINDOWS_PWA_AR.md`.

## رفع المشروع وتخزين اعتماد GitHub في Termux

من مجلد الحزمة المستخرجة شغّل `bash termux-eo.sh save` مرة واحدة لإدخال GitHub Username وPersonal Access Token (إدخال مخفي) ورابط المستودع. يحفظ السكربت الاعتمادات في `~/.config/almanthomh-eo-cn/github-credentials` بصلاحية `600` داخل مساحة Termux الخاصة، ولا يضعها في المشروع أو `.git/config` أو رابط Git. استخدم `bash termux-eo.sh status` لعرض الحساب دون التوكن، و`bash termux-eo.sh update-token` لتغيير التوكن، و`bash termux-eo.sh forget` لحذفه، و`bash termux-eo.sh push` للتحقق من EO VAULT ورفع الملفات المشفرة المحددة فقط. التخزين محلي كنص واضح محمي بعزل تطبيق Termux وصلاحيات الملفات؛ اختراق الجهاز أو صلاحية root قد يكشفه، لذلك استخدم Fine-grained PAT بصلاحية Contents: Read and write للمستودع المطلوب فقط، وألغِه إذا فُقد الجهاز.

لتثبيت مفاتيح المطور استخدم `bash termux-eo.sh install-keys /مسار/ALMANTHOMH_EO_CN_V5_DEVELOPER_KEYS.zip`. لفك المصدر استخدم `bash termux-eo.sh open-source`، وبعد التعديلات استخدم `bash termux-eo.sh seal-source` لإعادة التشفير وإنتاج ZIP جديد. لا ترفع مجلد المصدر المفكوك. لنسخ قيمة GitHub Actions Secret يدويًا استخدم `bash termux-eo.sh actions-key` بعد التأكيد، ثم أضفها في إعدادات المستودع باسم `EO_MASTER_KEY`.

## تشغيل الخادم

GitHub Pages وحده لا يشغّل FastAPI أو PostgreSQL أو WebRTC signaling. يلزم خادم Docker مع PostgreSQL ونطاق HTTPS. اقرأ `DEPLOY_AR.md`، واستخدم `.env.example` كقالب؛ لا ترفع `.env` إلى المستودع.

### غرفة الاسترداد الطارئ

1. تأكد من تفعيل TOTP لحساب المدير وضبط `TOTP_ENCRYPTION_KEY` في `.env`.
2. أنشئ مفتاح غرفة مستقلًا: `python scripts/generate-emergency-vault-code.py`. الرمز يظهر مرة واحدة فقط؛ لا تستخدم أي رمز سبق نشره في محادثة أو مستودع.
3. أعد تشغيل خدمة الويب، ثم افتح غرفة المطور وأدخل مفتاح الغرفة ورمز TOTP.
4. يمكنك تدوير مفتاح استرداد منفصل لأي خانة هاتف أو كمبيوتر. المفتاح يظهر مرة واحدة فقط ويخزن الخادم SHA-256 digest، ولا يحتفظ بالنص الأصلي.
5. استخدام مفتاح الاسترداد يحرر الخانة ويلغي اعتماد الجهاز والجلسات وجلسات المشاهدة؛ لا يعرض كلمة مرور المستخدم ولا يسمح بدخول حسابه.

### كود المطور (حصة الاستخدام فقط)

أنشئ كودًا عشوائيًا يظهر مرة واحدة باستخدام `python scripts/generate-developer-access-code.py`. لتدويره لاحقًا استخدم `--rotate`. يُخزّن الخادم بصمة SHA-256 فقط، ويمنح 24 ساعة استخدام يوميًا ولا يمنح دور ADMIN. أعد تشغيل خدمة الويب بعد التوليد.


## حماية المصدر EO VAULT

ملفات المصدر المحمية تحفظ داخل `vault/eo_vault.bin` مشفرة بتقنية AES-256-GCM. يتضمن `vault/manifest.json` بصمات SHA-256 لكل ملف ويوقع البيان بمفتاح Ed25519 خاص. يقرأ `vault_bootstrap.py` المفتاح من `EO_MASTER_KEY`، ويتحقق من التوقيع والبصمات قبل فك الملفات إلى مساحة مؤقتة. راجع `DEPLOY_AR.md` للقواعد والأوامر.


**ملاحظة مستودع GitHub:** ارفع الحزمة المشفرة فقط باستخدام سكربت التحديث الآمن. لا تستخدم `git add -A` بعد فك EO VAULT؛ ملفات العمل المفكوكة يجب أن تبقى على جهاز المطور.


## الرفع من ملف EO VAULT الخارجي

الملف الخارجي يحتوي على سكربت رفع صغير `scripts/termux-upload-sealed.sh` خارج الحمولة المشفرة. هذا السكربت نفسه مدرج ضمن `loader_files` وموقع ضمن بيان السلامة؛ يتحقق من EO VAULT أولًا ثم يرفع allowlist الملفات المشفرة وملفات التشغيل فقط. لا تستخدم `git add -A` على مجلد المصدر المفكوك. شغّل `bash scripts/termux-upload-sealed.sh` من مجلد الحزمة الخارجية بعد فك ZIP.
